# 告警通知

## 配置通道

系统设置中的“告警通知”支持飞书、企业微信和钉钉群机器人，默认关闭。

1. 在目标群创建自定义机器人，取得 Webhook 地址。
2. 在 Watch 选择对应平台，填写地址；飞书或钉钉机器人启用加签时，填写相同的签名密钥。使用关键词校验时，可将关键词设为 `ROS Watch`，所有通知均包含这个前缀。
3. 保存通知设置，点击“测试发送”，到群内确认收到。
4. 勾选告警类型并启用通知。测试发送使用已保存的通道，关闭自动通知时也能测试。

WebHook 仅接受对应平台的官方 HTTPS 地址。保存后地址和密钥不回显，留空会保留同平台已保存值；更换平台时需要重新填写地址。签名密钥可通过“清除已保存的签名密钥”移除。

微信通道指企业微信群机器人。通知配置保存在持久卷的 `control.sqlite3` 中，与账号和日志采集设置独立；Webhook 和签名密钥按凭据保存，备份也应妥善保管。

## 告警规则

| 类型 | 条件 | 默认选择 |
| --- | --- | --- |
| 连续登录失败 | 同一日志发送设备、设备名称、登录来源和账号，在 UTC 对齐的 5 分钟固定窗口内至少 5 次失败 | 勾选 |
| 非可信来源登录成功 | 日志有明确来源，且来源不在“可信管理来源”IP/CIDR 中 | 不勾选 |
| 磁盘、接收与写入异常及恢复 | 每 15 秒检查磁盘阈值、日志接收器和写入状态，状态变化时通知 | 勾选 |
| 疑似端口扫描 | 同一发送设备和访问来源，在固定窗口内达到不同目标端口数阈值，沿用日志管理中的扫描阈值 | 不勾选 |

“可信管理来源”填写正常登录路由器的管理客户端 IP 或网段，与“允许发送日志的设备”分开。启用非可信来源登录成功通知时必须填写。日志没有提供来源的 API 配对记录不推断来源，也不触发该类告警。

登录与扫描告警同类型、同设备和同来源冷却 10 分钟，登录还区分账号；存储与接收告警按状态变化通知。固定窗口可能漏掉跨窗口的分散尝试，ROS 日志采样及 UDP 丢包也会影响观察结果。

## 发送与运行状态

通知判断使用启用后成功写入的新日志，不回放数据库中的历史记录。状态检查和发送在独立后台任务执行，HTTP 超时为 5 秒，同一时间只发送一个请求；测试通知、自动通知及重试共同限制为至少间隔 5 秒。自动通知失败后最多重试 2 次，测试发送只尝试一次。网络超时后重试可能产生重复消息。

观察缓冲区与发送队列均有上限。超载时保留日志采集流程，通知处理可能丢弃，页面分别显示“通知观察丢弃”和“通知队列丢弃”。失败次数按实际失败请求计数，包括重试；平台返回成功不等于群成员已阅读。

发送计数、最近发送状态、观察窗口和冷却状态属于本次进程运行，重启后清零；通道配置保留。Watch 停机期间不能自行发送停机告警，服务存活检查需由外部监控负责。

## 接口

所有接口要求登录，POST 还要求有效 CSRF 令牌。

- `GET /api/notifications`：读取开关、平台、事件选择、可信来源、凭据是否已配置以及发送状态，不返回地址或密钥原文。
- `POST /api/notifications`：保存通道设置。`webhook`、`secret` 留空保留同平台已保存凭据；`clear_secret=true` 清除密钥。
- `POST /api/notifications/test`：使用已保存通道发送测试通知，检查 HTTP 状态及平台业务返回码。
